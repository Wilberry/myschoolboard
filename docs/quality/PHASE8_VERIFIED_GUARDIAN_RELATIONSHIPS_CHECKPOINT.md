## Next roadmap feature authored

The Phase 6 `StudentAccountLink` already represents an explicit, revocable STUDENT membership-to-pupil binding. A PARENT role alone does not establish a guardian relationship with a particular pupil. This phase adds an exact school-attested relationship foundation **without guessing identity and without granting anyone a result**:

- Additive Prisma `GuardianStudentRelationshipEvent` and migration `20261013200000_phase8_guardian_relationship_evidence`, with same-school composite FKs to exact StudentRecord, PARENT membership and school-owner actor; per-exact-pair trusted monotonically numbered immutable `VERIFY`/`REVOKE` history, reason, review flag and trusted timestamp. SQL rechecks active School under `FOR UPDATE`, active exact School Super Admin user/membership and current PARENT verified-email user plus current enrolled pupil (ACTIVE enrollment) for verification. It disallows repeated identical action, ensures first event is VERIFY, permits a subsequent re-verification only after revocation and permits revocation even after parent's role/account has become inactive. UPDATE/DELETE/TRUNCATE triggers prohibit mutating old attestation evidence.
- DB-only `inspect_private_report_recipient_relationship` accepts exact school, private composed report, pupil, proposed PARENT or STUDENT school membership and CURRENT School Super Admin user/membership. It repeats owner security and checks exact school/current enrolment for the composition's class/session, pupil identity present in the internally frozen composition (read only inside DB), latest school-adopted visibility preference, verified current recipient membership and email, and **either** an unrevoked existing Phase 6 `StudentAccountLink` for STUDENT or latest VERIFIED guardian event for PARENT. It returns solely `RELATIONSHIP_VERIFIED_NOT_RELEASED` or `NO_VERIFIED_RELATIONSHIP_OR_POLICY`; no grade/mark/answer keys/parent contact ever leave SQL. This status is **not** official result approval or an authorization token.
- Same-school School Super Admin-only private/no-store `GET/POST /api/schools/[schoolId]/guardian-relationships` for event history/append, and `POST /guardian-relationships/inspect` for the relationship diagnostic; strict requests forbid client-provided actor IDs, report status, grades, guardian access tokens or invented publication. User-verified relationship evidence check is required for VERIFY with a reason; REVOKE needs reason and exact existing pair. Server-gated owner workspace and school navigation; no student/guardian API or grade reader.
- Authored Vitest integration scenario with synthetic PARENT membership/email identity; owner/other-role/foreign-tenant denial; forged grant inputs; missing verified email; duplicate transition; verification and revocation ordinals; lapsed enrolment; inactive member and role loss; revoke despite role demotion; renewed attestation; immutable UPDATE/DELETE/TRUNCATE; existing STUDENT account-link diagnostic and no result disclosure. An added Node source/behavior guard is registered in both `npm test` and `verify:local:guards` without removing previous guards. D-063/ADR-049, authorization, module specification, roadmap/milestone and traceability records updated.
