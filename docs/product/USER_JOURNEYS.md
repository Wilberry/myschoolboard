# User Journeys

## School onboarding journey

1. Platform Super Admin creates a tenant record.
2. Subscription plan and lifecycle settings are assigned.
3. School Super Admin completes onboarding and configures identity, branding, and academic structure.
4. School administrators, HMs, and Principals are assigned roles.
5. Classes, subjects, and teachers are established.

## Student admission journey

1. Inquiry or application is registered.
2. Admission record is reviewed.
3. Student is accepted and enrolled in a valid class.
4. Guardian relationships, class history, and student status are created.
5. Student remains in historical records even across promotion or transfer.

## Attendance approval journey

1. Form Teacher submits daily attendance.
2. HM or Principal reviews pending attendance.
3. Approval, rejection, or return for correction happens.
4. Approved attendance becomes official or visible according to policy.
5. Corrections retain historical record and reason.

## Result publication journey

1. Teacher prepares result sheet.
2. HM or Principal approves or returns the sheet.
3. Result sheet populates report-card record state.
4. School Super Admin performs final publication approval.
5. Parent or student access is allowed only according to the school report visibility policy.

## Payment verification journey

1. Parent or school user submits transfer evidence.
2. Finance reviewer validates the evidence.
3. Payment is marked as pending verification, verified, or rejected.
4. Idempotent reconciliation protects against duplicate callbacks.
