# Accessibility and Responsive UX

## Accessibility standards

- Support keyboard navigation for critical workflows.
- Visible focus states and clear labels for forms.
- Sufficient contrast for text and interactive elements.
- Descriptive form validation messages.
- Mobile and screen-reader support for core dashboards and forms.

## Responsive requirements

- Attendance entry, assignment viewing, and parent dashboards must function well on mobile.
- Tables and lists should degrade gracefully on smaller screens.
- Navigation must remain clear on desktop, tablet, and mobile.

## Empty and error states

- Empty attendance, result, and dashboard states must communicate that no data is available.
- Validation and permission denials must be visible and actionable.

## Accessibility policy

Accessibility is a product requirement. It is not optional and must be validated with usability and QA reviews before final release.
