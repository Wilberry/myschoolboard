# Coding and Repository Standards

## Standards

- Keep modules explicit and tied to business domains.
- Apply tenant-aware logic at API and service boundaries.
- Add tests for permission and workflow changes.
- Preserve audit and retention metadata in all consequential state changes.

## Repository standards

- Maintain a single source of truth in the docs.
- Do not introduce contradictory requirement definitions.
- Update the roadmap and decision logs when a material change occurs.

## Current status

No code or repo tooling exists yet, so these are standards to be enforced as implementation starts.
