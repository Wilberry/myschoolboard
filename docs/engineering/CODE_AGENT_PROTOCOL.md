# Code Agent Protocol

This file defines the required agent discipline for implementation work.

## Required practices

- Read the root AGENTS file and documentation index before making edits.
- Trace the work to a requirement ID and acceptance criterion.
- Keep changes small, coherent, and auditable.
- Verify the exact behavior with targeted tests.
- Update requirements, roadmap, and decision records when behavior changes.
- Preserve the distinction between specified, proposed, implemented, tested, and deployed states.
- Treat the product requirements and approved decision records as the source of truth.
- Avoid inferring approval from an unanswered question or an unimplemented design.
- Preserve historical academic and financial records; do not silently rewrite evidence.
- Record new decisions in the decision log or ADR system.
- Update requirements traceability when scope or behavior changes.
- Report files changed, checks performed, failures, unresolved issues, and Git status.
- Avoid broad refactors unrelated to the task.

## Prohibited behavior

- Silent requirement rewriting
- Removing tests to force a green result
- Destructive repo changes without explicit authorization
- Cross-tenant or permission bypass
- Claiming completed work without validation evidence
- Expanding implementation scope without explicit authorization
- Writing secrets into code, documentation, logs, screenshots, or commits
- Misreporting a push, migration, deployment, or test result without actual command evidence
