## Phase 8 end-to-end result publication and school recipient access — AUTHORED / VALIDATION BLOCKED

The code now connects the entire mandatory RES-REQ-001 chain: teacher-authored source sheet → independent HM/Principal reviewed approval → explicit School Super Admin final academic approval → frozen class/subject source packet → school-adopted grade-scale/aggregation official grade composition → **separately audited School Super Admin recipient release** → **currently school-configured verified student/guardian read** and print-friendly subject report. Grade and identity fields come only from exact immutable frozen evidence; no browser marks or answer keys. Every recipient release is a new immutable school/session/term/class/subject ordinal pinned to current school-adopted visibility policy, grade context, actor and reason. A policy adoption without owner release exposes nothing; a new policy pauses previous recipient reads. A corrected result requires new teacher evidence, fresh independent academic approval, new frozen composition and new owner release; historical versions persist.

The four explicit modes are `SCHOOL_ONLY` (no recipients), `STUDENT_ONLY` (only exact active unrevoked school-student account link), `GUARDIAN_ONLY` (only exact current unrevoked attested guardian link), and `GUARDIAN_FIRST_ACK` (valid guardian can read; verified child can read only after a currently valid guardian explicitly acknowledges the **exact release**). Guardian receipts are separate immutable DB audited events and do not grant access to sibling or other versions. Recipient GET has no child-ID input, only the caller's school; PostgreSQL projects at most 100 released subject rows after final same-school role/student/enrollment/revocation/latest release/current policy checks, sends no private sources or answer keys, and returns private no-store/noindex responses. Authenticated browser portal groups subject grades into printable session/term/class child summaries; browser Save as PDF creates no public server file and implies neither an invented pass mark/rank nor fully published curriculum.

**Safety gate:** `PHASE8_REPORT_RELEASE_ENABLED` and `PHASE8_REPORT_RECIPIENT_ACCESS_ENABLED` default false; release and recipient handlers fail closed until disposable-Postgres runtime security tests, entire cumulative Phase 6–8 migrations/authz/TypeScript/build/browser checks, strict npm security audit and independently approved operational release. The implementation is on a non-default draft development branch; it has NOT been migrated, run with live users, enabled, merged or deployed. No GitHub Actions triggered. D-063/ADR-049. ## Phase 8 explicit report-category aggregation policy (AUTHORED; NOT VERIFIED)

An active School Super Admin must adopt an immutable school-level aggregation revision `ReportAggregationRuleRevision`: `EQUAL_ASSESSMENT_BPS` rounds each approved assessment's earned/possible score to integer basis points, then rounds the equal assessment mean within QUIZ, TEST, EXAM; or `POOLED_CATEGORY_POINTS` sums earned and possible points within each category and rounds the category ratio once. Both modes apply the exact prior school-adopted QUIZ/TEST/EXAM weights (100%-sum) and round the weighted final score to integer basis points, using an explicitly adopted `HALF_UP/FLOOR/CEILING` rule on all divisions. A separate adopted school grading-scale revision controls displayed precision and classification bands. **No aggregation method, rounding mode, scale, pass/fail or grade thresholds default silently.**

The new `simulatePrivateReportComposition` is pure arithmetic over an already privately frozen result-source packet and explicit pinned revision IDs, rejecting invalid/duplicate/unscored student marks, missing positively weighted category, mixed weight versions and absent scale policy. Its output is **PRIVATE_COMPOSITION_SIMULATION_ONLY**, not persisted, official, or exposed by any HTTP endpoint. Existing immutable private packet evidence is unchanged. School-owner private GET/POST manages rule history, never raw marks. Future official report composition must independently revalidate all current approval/tenant/source/policy decisions and store immutable report evidence with exact versions, then obtain separate release authorization; no student/guardian visibility, PDF, export or public result yet. D-059/ADR-045.

## Scope

Result sheets, report-card generation, approval, publication, and visibility policies.

## Mandatory workflow

1. Teacher prepares assessment and result-sheet data.
2. HM or Principal reviews and approves or returns.
3. Approved data populates report-card records.
4. School Super Admin performs final publication approval.
5. Student and parent access follows the configured visibility policy.

## Publication rules

- HM/Principal approval does not equal final report publication.
- A report card is official only after the School Super Admin’s final approval.
- Corrections after approval or publication must be versioned and auditable.
