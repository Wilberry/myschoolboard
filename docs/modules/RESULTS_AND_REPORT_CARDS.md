## Phase 8 confidential one-pupil multi-subject term preview — INTERNAL ONLY

School Super Admin may inspect one actively enrolled pupil's approved term grades for each distinct currently ACTIVE teacher-assigned subject in the pupil's exact school/session/class. The strictly validated private `POST /api/schools/[schoolId]/private-term-grade-previews` derives current owner identity and uses a serializable School-row-locked transaction to verify term and active enrollment, find subject assignments, require newest unambiguous private compositions and invoke the existing `read_private_owner_one_pupil_grade_preview` **for each subject**. That SQL function independently checks the current original TEACHER/HM or Principal reviews and recomputes all frozen class grades, returns only that pupil's subject details, and writes an immutable per-read audit. If any subject is missing or stale, **all** per-subject previews and audit writes roll back without a partial response. A private table lists subject/percent/grade/remark; no term mean, ranking, pass/fail, promotion, report download, PDF or visibility for students/guardians. The included subject set comes from **current exact-session ACTIVE teacher assignments, not a school-approved complete subject registry**. It must not be used to certify official report-card subject completeness or authorise a result publication. P-004 and full PostgreSQL/quality acceptance remain blockers. D-066/ADR-052.

## Scope

Result sheets, report-card generation, approval, publication, and visibility policies.

## Mandatory workflow

1. Teacher prepares assessment and result-sheet data.
2. HM or Principal reviews and approves or returns.
3. Approved data populates report-card records.
4. School Super Admin performs final publication approval.
5. Student and parent access follows the configured visibility policy.

## Publication rules

- HM/Principal approval does not equal final report publication.
- A report card is official only after the School Super Admin’s final approval.
- Corrections after approval or publication must be versioned and auditable.
